# Находки: app-ABI, LFI-каталог, шифрование модулей (ATJ2273S, MP5 X7)

## 1. Шифрование LFI (уточнение)
- Keystream LFI **строго 512-периодичен**: зона `raw[0x1400:0x2000]` = 6 идентичных 512-байтных
  блоков (проверено: `block[k]==block[0]` для k=0..5). Значит `K = raw[0x1400:0x1600]` — верный ключ.
- `dec[i] = raw[i] ^ K[i % 512]`.
- **НО** каталог LFI (`LFI_DIR @0x200`, 32-байтные записи) расшифровывается корректно только
  для первых записей (FWINFO, OEMO, OEM.KO, SYSCFG, FS.KO — имена+метаданные верны),
  далее метаданные «плывут» (MFP — 8 байт имени, LIBC — 4, дальше — бинарь).
  → вероятно, помимо общего XOR есть отдельная защита заголовка/каталога (нужен доп. разбор).

## 2. Модули системы (LFI) зашифрованы ВТОРЫМ слоем
- ELF-заголовок и program headers модулей (119/123/124, 050-065 и др.) — **открытые** и валидные
  (`ET_EXEC`, `EM_MIPS`, `e_entry`, PT_LOAD), но **тело сегмента — шифр**:
  - нет MIPS-прологов `0x27bd` (addiu sp,sp,-N): `pro=0` во всех модулях;
  - перебор 512 фаз XOR, zlib/gzip/bz2/lzma, NOT, byte-swap, реверс слов — **не помогают**;
  - `raw` (без XOR) и `dec` (с XOR) одинаково «шумные».
- Следствие: **дизасм модулей десктопа/лаунчера (119/123/124) пока невозможен** —
  это блокер для вытаскивания `LAUNCHER_API_ID` и прототипов `sty_*`/`menuview_*`.

## 3. Каталог LFI (расшифрованная часть) — достоверные записи
`LFIHead@0`: flag `55 aa f2 0f`, `Version@0xD0="1.1.11.230105"`, `VID=0x10D6`, `PID=0x1101`,
`DeviceName="Media Player"`.
`LFI_DIR @0x200`, запись 32 Б: `name[11]|attr|u32 a|u32 off(в секторах 512)|u32 size|u32 ck1|u32 ck2`.
Достоверно: FWINFO.BIN(0x2000,512), OEMO.BIN(0x2200,1024), OEM.KO, SYSCFG.SYS(0x8d65 сект),
FS.KO, затем CARD.KO, KERNINFO.KO, UMONITOR.KO, GPU.KO, HANTRO.KO, TVOUT.4_8 …

## 4. ABI приложения (.app) — валиден и полностью читаем
`.app` (на SD, НЕ зашифрован) = ELF32 LE MIPS `ET_EXEC`, **свой load-base** у каждого
(`calculat.app`→`0x65800000`, `setting.app`→`0x67000000`).
- `.init` (секция первая) = `addiu sp,sp,-N; sw ra; jal <init_fn>; lw ra; jr ra`.
- `e_entry` = **`main`**, вызывается загрузчиком с 3 аргументами (`a0,a1,a2`); сам зовёт `.init`.
  Пример `setting.app`: entry `0x67010ef0` → `jal 0x67000000`(.init), затем init-функции.
- `.text` **не strip** — символы: `_menu_init`/`_menu_deinit` (фреймворк меню), `g_menu_entry`
  (глобальная таблица пунктов), обёртки **`commonui_apiNN.S`** (NN = 15,23,31,…,1004 — индекс API).
- Сисколлы приложения совпадают с `actsemi` (проверено, `syscall_check.txt`).

## 5. Состав SD «zapps» (ch73172_HD)
`<app>/<app>.app` + `s480272_style_1/<app>.res|.sty|_<lang>.str` + данные.
Приложения: setting, video, music, photo, ebook, recorder, calendar, watch, emulator,
tvoffset, **game_launcher** (ROM NES/GBA), `font/attfv1.ttf`, `sys/actplaylist.db`.
Все `.app` — открытые ELF; `.res`=контейнер `RES\x19` (RGB565), `.str`=строки локализации.

## 6. Что это даёт для своего лаунчера
- Можно собрать **свой `.app`** (ELF, `.init`+`main`), использовать AOS-API (=actsemi) —
  это выполнимо без дизасма закрытых модулей.
- Замена **встроенного десктоп-модуля** в LFI — **заблокирована** шифром модулей (п.2).

## 7. ИСПРАВЛЕНИЕ
Весь LFI расшифровывается ровно (0/16.25MB отклонений) — keystream 512-байтный, ключ верный.
Тела модулей LFI упакованы пофайлово (не XOR; не zlib/gzip/lzma; ~15% нулей -> структурированная
таблица + заголовок 0x40 Б). Загрузочные модули BREC (key.bin/mfp.bin/card.bin/brecf03.bin)
- полностью открытый код. Загрузчик/распаковщик LFI искать в открытом MBREC/BREC.
